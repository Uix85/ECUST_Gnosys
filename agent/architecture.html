核心原则：只有 task 会在 Agent 停止后检查未完成 Goal；有就继续唤醒。 chat 不碰 Goal，Agent 停止后直接返回。

判断点

循环里真正决定走向的 5 个 if。

1

mode == task ?

task 先 add_goal；chat 直接加载 context。

2

task 且有 goal ?

是则 load_context(goal.id)；chat 用已有 context。

3

mode == task ?

task 走 complete_goal；chat 走 save_context 后直接返回。

4

task 还有未完成 Goal ?

没有就返回输出；有则继续唤醒 Agent。

5

超过 max_goal_rounds ?

到达上限返回最后输出，避免无限循环。

两种模式，同一个循环

task 是预置了 Goal 的 chat；chat 是不预置 Goal 的无头循环。

mode="task"

预置 Goal，未完成就继续唤醒

启动时执行 add_goal(root_goal)，所以第一次 next_unfinished_goal() 一定能拿到目标。

  • 每轮 load_context(goal.id)
  • Agent 返回后 complete_goal
  • 未完成 → 回到 while True
mode="chat"

无预置 Goal，Agent 停止即返回

启动时只加载 chat context，不写 Goal，也不查 Goal。Agent 停止后保存 context 并返回。

  • 没有 Goal，goal=None
  • 每轮 save_context
  • Agent 停止 → return output
一句话：Runner 是内层的模型-工具循环；agent_loop 是外层的 Goal 唤醒循环。 两者分开，所以 chat 和 task 可以共用同一套执行路径。
