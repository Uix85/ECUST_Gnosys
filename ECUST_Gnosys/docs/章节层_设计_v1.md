# 章节层（L2）设计 v1

> 状态：设计稿，待审查。依据：《项目申报书》"章节层＝论证脚手架"三要素（承上启下位置／核心论证步骤／关键论证转折点）＋ `docs/章节层_第二章知觉_v2.md`（第二章可用稿，本设计的参照答案）＋ 与本项目负责人的逐条确认。
> 适用书：**《精神现象学》**（贺麟译本，txt 入库，标题树可用）。江村经济的结构层切分问题另立项，不阻塞本项。

---

## 1. 目标：章节层要做出什么

章节层夹在两层之间，跨度最大：全书层完全不处理具体内容，语义层只处理具体内容（一段一句）。章节层要同时做到：

1. **统筹全章**：总结一章总体的论证逻辑，说明核心要素。
2. **读前定位**：读者读具体正文**之前**，就能知道各部分在干什么——像向别人陈述代码用途：有的区块是 `import` 式无逻辑内容（版式、丛书页、全局设定），有的是有明确意图的"函数定义"（概念界定），有的是有具体结构的论证区。
3. **多级标题逐级上升**：作者标好的层级要原样保留并逐级解释。几步论证构成一个区块（最深一层）→ 几个区块间的论证递进 → 上升到上一层 → 最后上升到章标题。
4. **承担语义层无法跨段的部分**：跨段构成的论证关系在章节层讲，语义层只讲段内与句内。
5. **表达注意侧重**：不平均用力，核心区块要标出来。

> **本设计的重心**：判断侧（§5 判定标准、§8.2 质量验收）是主体，决定产出好不好；
> 机械侧（§2–§4、§6–§7）只保证"形式不崩、可交付、可复用"。不要按篇幅比重去读它——
> 机械侧写得多是因为它必须逐字精确，不是因为它是重点。

**骨架来源（关键决定）**：章节层**沿作者给的标题树逐节点解释**，不让模型自由划块。模块切分是机械获取的（`book_outline`），不一定完全对准逻辑切分；但对章节层影响有限——作者一般能把握住基本的逻辑切分，机械切分与逻辑切分差别不大（语义层才差别巨大：它的段句是纯机械切分，一旦跨段构成一个论证区就全错）。模型的工作是**在每个标题区块下明确逻辑状态**，而不是重新划界。

## 2. 数据契约

### 2.1 表结构

`chapter_layer` 通过既有 `_ensure_columns` 增加两列（无需迁移脚本、不改已有列）：

```
content      TEXT     ← 读者看的 Markdown（由代码渲染，见 §6）
blocks_json  TEXT     ← 单一真源：带标注的标题树（见 §2.2）
chapter_idx  INTEGER  ← 逻辑章索引（消费者契约，见 §2.3）
model_version TEXT
updated_at   TEXT
```

### 2.2 blocks_json（模型唯一要交的东西）

```json
{"chapter": {"problem": "本章的问题（1 句）", "forecast": "结论预告（1 句）",
             "ascent": "从最深一层几步论证 → 区块 → 区块间递进 → 全章的上升叙述",
             "carry_over": "承上一句", "hand_over": "启下一句"},
 "nodes": [
   {"node_id": "n0", "level": 0, "title": "第二章　知觉；事物和幻觉",
    "anchor": {"from": 0, "to": 37, "from_fp": "…", "to_fp": "…"},
    "role": "chapter", "purpose": "…", "children": [
      {"node_id": "n0-preamble", "level": 1, "title": "章首导语（原文未标）",
       "anchor": {"from": 1, "to": 3, "from_fp": "…", "to_fp": "…"},
       "role": "setting", "purpose": "立章程：对象为本质、知觉为非本质",
       "weight": "core", "focus": "章程就是全章的检验对象",
       "argument": "…", "to_next": "这份章程逼出第一节的搭建", "steps": ["①…", "②…"]}]}],
 "turning_points": [{"node_id": "n2-2", "label": "转折点一", "pos": 13, "text": "…"}],
 "handoff": ["…"]}
```

- `node_id`：`n{chapter}` 为章节点，子节点按路径命名（`n0-1-2`），供转折点引用。
- `level`：**相对章的深度**，章 = 0，往下依次 1、2…（与 `book_outline` 的 `level` 同义）。
- `anchor`：该节点覆盖的段落区间，含首尾段指纹（书重新切分后可判断锚点是否失效）。
- `role` 闭集：`chapter`（章本身）／`frontmatter`（版式、丛书页、页眉——无逻辑内容）／`setting`（全局设定，像 import）／`definition`（有意图的概念界定）／`argument`（论证区）／`transition`（过渡）／`recap`（收束复盘）／`aside`（附注旁支）。
- `weight`：`core`／`support`／`minor`，`core` 可给一句 `focus`。
- `steps`：几步论证构成这个区块。**只对 `weight=core` 的节点要求**（见 §5.8）。
- 章首在第一个子标题之前、章尾在最后一个子标题之后的段落，各作一个隐式节点（`n0-preamble` / `n0-postamble`），title 用「章首导语（原文未标）」。

### 2.3 存储键

`chapter_id`（外键，保完整性）与 `chapter_idx`（逻辑章索引，消费者用）并存，**读路径以 `chapter_idx` 为准**。
详见 `docs/定位系统_设计_v1.md`：本项完成后 `chapter_idx` 是唯一对外章坐标，`chapter_id` 只作内部外键。

实情（实测）：索引映射不是固定偏移——

```
精神现象学：chapters 表 11 行 vs 逻辑章 9 个
   spine 0 = 书名行（无逻辑章）｜spine 2 = 误切成长句的章（无逻辑章）
   ci=0 → spine=1；ci≥1 → spine=ci+2
江村经济：17 = 17 一一对应，但 chapters.title 被拼进了正文
```

因此前端 `reader.html` 现有 ~60 行"章标题前缀模糊匹配"是必然的绕路。加 `chapter_idx` 后前端可直接用阅读器自己的索引。**切换读取路径要动 `auxiliary_reading.py` 与 `reader.html`，与另一会话的改动有冲突风险：加列本身不改行为，先做；切换读取路径单独一步、动手前确认那两个文件没在改。**

### 2.4 旧稿

现有 9 章旧稿（约 8.6 万字，`chapter_id` 2,4–11）先导出到 `tmp/legacy_chapter_layer/<book>/<chapter_idx>.md` 作对照，DB 直接覆盖。`tmpuke_eepn` 那条把 L1 文本写进 L2 的污染直接清。

## 3. 输入材料（materials，一次注入）

| 键 | 内容 | 实测规模 |
|---|---|---|
| `chapter` | `chapter_idx`、标题、段数、前后章标题 | 小 |
| `tree` | 标题树 + 每节点区间；每段一行导航 `P12 [小节二·第一圈] 概括（≤80 字，标点处断）` | 最大章 2.7 万字（第六章） |
| `prev_handoff` | 上一章 `blocks_json.handoff`；没有就明说"无前章收获" | 小 |
| `book_layer` | L1 全书层文本，标注"可靠性低（当前为 558 字占位）" | 558 字 |
| `glossary_hits` | 术语表命中条目（**预筛：只放命中的**，不塞全表 4500 字） | 小 |
| `existing_l2` | 本章旧稿（若存在） | 0.5–1.4 万字 |
| `l3_gaps` | 哪些段没有 L3 概括（这些段必须读原文） | 小 |

导航条数实测：精神现象学 9 章共 1738 段，L3 覆盖 1425 段（82%）；截到 ≤80 字后全章导航最大 2.7 万字（第六章）、最小 2.4 千字（第二章）。

**产出规模**：不设向上限——写多少是模型的侧重判断，不是可预设的常数。可以参考的是下限与量级："每个节点一句作用＋递进"必须全覆盖，所以下限由节点数决定（实测全库 235 个节点）；若模型把较多节点判为重点，总产出会明显变大（旧稿 5,117–14,193 字/章是参考量级）。**装不下时由管线按树分片**（§6），不用合格线压数量。

## 4. 任务形状

- **一章一个任务**（9 个任务）。循环：读树与导航 → 判断各节点逻辑状态与侧重 → 对 `core` 节点 `read_text` 精读原文 → 写节点标注（全节点一句作用、core 节点展开）→ 组装章级总纲与转折点 → 交卷。
- 预算：60 次请求 / 40 次工具调用（实测预期 15–25 次工具调用，与章大小无关）。
- **工具 0 新增、技能 0 新增**：复用 `book-reading`（`read_text` / `search_text` / `read_outline` / `read_notes`）。列表相同，差异只在 materials、prompt、validator——这是工具按数据源收敛后的直接红利。

### 4.1 运行入口

**建议：命令行运行器 + 直接写库**（`tools/structure/run_chapter_layer.py --book … --chapter 2`），不复用 L3 那套 `run/task/event/pending/adopt` 机器。理由：那套是为 1424 条逐段笔记的批量审核建的；章节层只有 9 章，逐章人工过一遍（对比旧稿与 v2 稿）比建审批流便宜。以后要统一 Web UX，把运行器包一层端点即可。

运行器行为：`--dry-run` 只产出不写库并打印；写库前自动导出旧稿到 tmp；写库时同时写 `content`、`blocks_json`、`chapter_idx`、`model_version`。

## 5. 判定标准（进任务提示，不进技能）

> 这一节是**质量的全部来源**。validator 只能防形式崩坏，防不了"正确的废话"；所以判定标准必须写成
> **循环里可反复使用**的形式——不只是提纲，还要有反面样本与自检动作。

### 5.1 基本要求（自 v2 稿 §F）

1. 每个节点先答**作用**（这部分干什么），再谈论证；把版式行判为 `frontmatter` 一句话带过。
2. 区块概括的对象是**论证动作**，不是段落内容：只答"确立了什么／自身带什么矛盾／为什么不能停"。
3. 推演禁止并列表述（"接着…又…"），必须写"它确立了 X → 但 X 要求 Y → 而 Y 与 X 互斥 → 意识被迫承认 Z"。
4. 全部逻辑必须长在正文骨架里：抽掉所有节点标题与锚点后，章级总纲 + 各节点 purpose/argument 仍必须是一篇连贯的论证说明。
5. 术语严格沿用贺麟译名，首现括注一个白话等价物；解释用平实现代白话，一步一个箭头。
6. 每节点至多 1 个比喻（优先用原文自带意象）、至多 1 句原文整句引用；客观陈述语气。
7. 禁令：不复述单段内容（语义层的活）；不解释单个术语的定义本身（概念层的活，改为挂接）；不引入译本之外的二手解读；禁用口语化私人比喻（甩锅、爆雷、账本、钉死）与自造新词。
8. **侧重完全由模型判断**：所有节点都要写 `purpose`＋`role`＋`weight`；所有内部节点都要写 `to_next`；哪些节点是 `core`、每块展开多详，不设条数上限、不设字数指标。（反面教训：用"区间长度"机械代理→失控到 16 万字；换成"core 条数/字数"也是拿可数的东西当判断的替身。判断归模型，形式才归代码。）

### 5.2 反面样本（直接写进 prompt，比正面要求更有力）

**① 段落复述 —— 不是论证动作**

```
✗ 本段说明知觉的对象是事物，事物有许多特质。
✓ 把对象立成"具有许多特质的共同的东西"，是为了让它能被规定；
  而规定要求排斥——排斥装不进"又"，于是必须另立"单一"这个环节。
```
怎么判：凡句子能原封不动地写成该段 L3 概括，就是段落复述。

**② 并列式伪递进**

```
✗ 接着意识又试了一种办法…然后又改认…最后孤立地抓住一个特质。
✓ 它确立了 X → 但 X 要求 Y → 而 Y 与 X 互斥 → 意识被迫承认 Z。
```
怎么判：把任何一步单独抽走，若后文依然成立，那就是并列，不是递进。

**③ 正确的废话**

```
✗ 本章讨论意识与对象的关系，论证逐步深入，最终得出重要结论。
✓ 章首那份"对象＝本质、知觉＝非本质"的章程，在第三节最后一句"只因"被撤除时
  亲手撕毁：对象成了它自身的反面。
```
怎么判：把它换到同一书的另一章，如果照样成立，就是废话。

**④ 平均用力**

```
✗ 三个小节各写 300 字，包括那个只起交代作用的过渡段。
✓ 判决节点展开（steps＋argument）；过渡段一句话带过。
```

### 5.3 交卷前的自检动作（模型自己做，逐节点过一遍）

| 字段 | 自检问句 |
|---|---|
| `purpose` | 只看这一句，读者知不知道这块在干什么？ |
| `argument` | 有没有说清"它确立的规定自身带什么缺陷"？ |
| `to_next` | 为什么不能停在这里？下一步是被什么逼出来的？ |
| `weight` | 如果全章只能留三个节点，留哪三个？（用这个反推 `core`，而不是均匀分配） |
| `ascent` | 从最深一层读到章标题，这条线能不能一句话说清？ |
| 全篇 | 把 title 与 anchor 全去掉、只按顺序读 purpose/argument/to_next，会不会出现指代不清或跳跃？会就重写 |

## 6. 合格线（validator 逐条）

**先划界：判断归模型，代码只管形式。** 章节层的核心工作——哪个节点是什么作用、哪些是重点、写多详——全是**判断**，只能由模型在任务提示下做。validator 是代码，**只查可数的形式**，不碰判断。

| 归谁 | 做什么 |
|---|---|
| **工具**（代码，零判断） | 只取事实：正文、检索、结构、已有产出（现有 4 个，无新增） |
| **管线**（代码，零判断） | 机械组装输入（树、区间、每段一行导航、L3 缺口、命中的术语条目）；容量不够时按树分片；预算与重试 |
| **任务提示**（模型） | **全部判断**：每节点作用与 `role`、侧重（`weight`/`focus`）、详略、区块间递进、章级上升、转折点识别 |
| **validator**（代码，零判断） | 只查形式：结构完整性、字段存在、字数上限（显示常量）、引文逐字可核、禁令词、产品条数 |

| # | 判据 | 说明 |
|---|---|---|
| 1 | 节点全覆盖标题树，`level` 与树一致，`node_id` 唯一 | 不许错层、不许漏节点 |
| 2 | 锚点不重叠、递增，且**恰好拼满全章段落** | 比"覆盖 ≥80%"强；含章首导语与章尾 |
| 3 | 每节点有 `purpose`；内部节点有 `to_next`（末节点除外）；若 `weight=core` 则必须有 `argument` 与 `steps`(2–4)；`frontmatter` 节点免展开 | 只查"有没有"，不查"几个" |
| 4 | `role` 在闭集内；`weight` 在闭集内 | 枚举成员，机械可查 |
| 5 | 章级 `ascent` 非空；`turning_points` 3–4 处且 `node_id` 真实存在 | 条数来自申报书硬指标，是产品要求不是判断 |
| 6 | `handoff` ≤2 条 | 同上（v2 稿 §F 定） |
| 7 | 格式上限：`purpose` ≤60 字、`argument` ≤300、`steps` 每步 ≤120、`to_next` ≤80、`focus` ≤40（超了就是显示/交互预算） | 这是**显示常量**，不是对内容重要性的判断 |
| 8 | 禁用词正则：甩锅\|爆雷\|账本\|钉死\|我们读者\|你会发现 | |
| 9 | 引文若出现，须逐字出现在本次已读原文里 | 复用既有 `_sources` 核验 |

**validator 明确不查**（查了就是把判断偷偷交给代码）：

- ✗ core 节点有几个、哪几个——**侧重是内容判断，归模型**。硬压条数会逼它把该展开的区块降成一句话（75 节点的第六章）或给短章凑数。
- ✗ 全章产出多少字、每块写多少——字数只是结果的影子，拿它当合格线会向"凑字/减法"偏离。
- ✗ 论证好不好、递进对不对、转折点选得准不准。
- ✗ "抽掉锚点后仍连贯"——只能写进 prompt 要求模型自检。

**容量问题归管线，不归 validator**：若某章一次生成装不下，**按树在固定层切分**（机械规则：默认切在章下第一层，每个子树一片），每片只产出该子树的节点标注（锚点与树结构不变），再由一个小的汇总任务写章级总纲与切点处的 `to_next`。这样"侧重"可以完全自由，而"装不下"由可数的机制处理。

## 7. 渲染（blocks_json → Markdown）

渲染函数（约 30 行）产出读者看的 `content`：

```
# 第二章　知觉；事物和幻觉
**本章的问题** … **结论预告** …
**全章论证主线**（ascent）
**承上** … **启下** …

### [一、事物的简单概念]（作用：搭骨架）
重点 ｜ 任务 … ｜ 推演 ①…②… ｜ 去向 …
### [二、事物的矛盾概念] …
## 关键论证转折点
| # | 位置 | 内容 |
## 章末收获（移交下一章）
```

模型只交结构化 JSON，Markdown 由代码渲染：避免两份不一致，validator 只需校验一份。

## 8. 验收与试点

### 8.1 无模型自检（代码，硬门）

`tools/structure/check_chapter_flow.py`：材料组装与规模 + validator 正反例 + 渲染往返，并入测试套件；validator 正反例加 `tests/test_chapter_layer.py` 单测。这些只能证明**形式不崩**。

### 8.2 质量验收（人，有否决权）

形式全过不等于可发布。质量这一关明确由人参与（判断归人/模型，形式归代码），用下面 3 条**可抽查的信号**：

| # | 信号 | 怎么抽 |
|---|---|---|
| 1 | **抽掉锚点仍连贯** | 把节点的 title/anchor 全去掉，只按顺序读 purpose/argument/to_next |
| 2 | **读前定位成立** | 随机取 3 个节点，只看 `purpose`，问"我知不知道这块在干什么" |
| 3 | **论证动作 vs 段落复述** | 随机取 3 段 `argument`/`steps`，找"接着…又…"式并列句与可原封不动变成 L3 概括的句子 |

### 8.3 迭代闭环（第二章为样本）

```
第 1 轮：跑第二章
  → 我逐节点自评（上述 3 条信号）+ 标出可疑处（具体证据：哪句是复述、哪个节点读完仍不知在干什么）
  → 你只看标红处，说改哪里
第 2 轮：改 prompt → 重跑同一章
  → 与上轮对照：是变好了，还是只是变了
重复至过线 → 才铺序言、第六章 → 才是其余章
```

- **否决权**：没过线的章**不写库**（`--dry-run` 先看，或写为草稿标记），不静默发布。
- **旧稿不清**（导出到 tmp 作对照基线），否则无从判断"比原来好"。
- 每轮记录：prompt 版本 + 评分结论（可追溯，也方便以后回看哪一版怎么变的）。

### 8.4 其余试点

| 试什么 | 用谁 | 看点 |
|---|---|---|
| 噪声节点 | 序言（17 节点 / 267 段） | `【丛书名】`（吞 P2–P123）能被判为 `frontmatter` 且不污染其他节点 |
| 规模与深树 | 第六章（75 节点 / 461 段 / 13 万字，最深 L6） | 导航 2.7 万字不爆；大章是否需分片（由实测容量定） |
| 无 L3 输入 | 江村经济 | 本项**不做**（结构层另立项），只在实现时确保不因缺 L3 而崩 |

**顺手修一处结构规则**：`【…】`（鱼尾括号）行不该当标题。当前序言的 `【丛书名】` 被识别为 L2 标题并吞掉 122 段（序言 46%），同一个错误还经 `section_context` 污染 L4 材料里的 `context_title`。全库只此 1 处，改规则 + 加断言即可，一处修改同时治 L2 与 L4。（`book_outline.section_context` 有 6000 字上限兜底，所以没有把 L4 材料撑爆。）

## 9. 已知边界

1. **江村经济前提不成立**：标题树空（16 章里 11 章 0 标题），切分本身错——`1．家，扩大的家庭　　家庭这个名词…` 是段内文字（该段 907 字），页眉"江村经济"被切成独立 4 字段。它的结构层修复（段内标题二次切分、页眉剔除、章标题粘连拆开）另立项，影响 L2/L3/L4/读者切分四处。
2. **v2 稿的锚点不能直接复用**：v2 稿按 `docs/_第二章知觉_原文.txt` 编到 P1–P24，而 DB 第二章是 38 段，不是同一套切分；内容可对照，锚点不可对照。
3. **深度不稳定**：层级从 0 层（第一章只有章标题）到 6 层（第五、六章）不等。所以详略不用层级号、也不用区间长度机械定，而用 `weight`（侧重）——后者本来就是章节层要做的判断。
4. **大章容量**："每个节点一句作用＋递进"必须全覆盖，所以产出下限由节点数决定（实测 235 节点）。上限不预设——侧重是判断，写多少由模型定。若某章一次生成装不下，由**管线按树在固定层分片**（机械规则，见 §6），不靠合格线压数量。分片的触发阈值等第二章跑通、看到真实容量后再定。

## 10. 本项不做（YAGNI）

- 不做 L1 全书层（章节层的"承上"只需上一章的 `handoff`）。
- 不做前端多段高亮 UI（只把 `blocks_json` 与 `chapter_idx` 存到位）。
- 不做关系网络（`relations`）。
- 不做江村经济切分修复（另立项）。
- 不新增工具、不新增技能。
