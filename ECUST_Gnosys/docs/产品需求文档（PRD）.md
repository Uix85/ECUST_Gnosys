## 1. 产品定位与核心价值

### 1.1 一句话定义

以 **Agent 为执行核心**、以 **原文证据为约束**、以 **任务校验为终止条件** 的哲学社会科学辅助阅读工作台。

### 1.2 解决的核心问题

| 痛点 | 现有方案局限 | 本产品方案 |
| :--- | :--- | :--- |
| 读者缺乏理解长文本所需的背景知识 | 通用 AI 问答脱离上下文、引文不可核验 | Agent 基于原文生成四层辅助内容，每条绑定章/段坐标和文本指纹 |
| 长篇论证逻辑难以把握 | 现有工具只做摘要/检索，不重建论证结构 | 全书层 + 章节层主动生成结构地图和论证路线 |
| 术语多义性导致理解偏差 | 传统注释静态且覆盖有限 | 概念层动态生成义项辨析 + 跨章证据 |
| AI 生成内容不可信 | 自由文本无校验、无来源 | 结构化输出 + 逐字引文校验 + 失败退回修改 |

### 1.3 核心设计原则

1. **辅助不替代：** AI 生成内容作为辅助材料呈现，读者结合原文形成自己的判断，不把模型输出直接当作定论。
2. **证据可回溯：** 每一条解释、论证步骤或概念说明尽可能绑定章节、段落、文本指纹和原文引文，读者可从辅助内容回到原文对照。
3. **任务有边界：** Agent 通过受控工具访问数据，不直接操作业务数据库；工具返回材料自动附带章/段坐标和指纹。
4. **终止有标准：** 模型自由文本不视为完成标志，必须通过结构化校验器检查（字段完整、节点覆盖、引文逐字匹配、指纹一致）才视为任务完成。

## 2. 系统总体架构

### 2.1 分层结构

```
┌──────────────────────────────────────────────────────────┐
│                  阅读器前端（静态 Web）                     │
│  左栏目录  │  中栏正文  │  正文右侧简短解释  │  右栏四层+对话  │
├──────────────────────────────────────────────────────────┤
│                Server 业务层（FastAPI + SQLite）            │
│  书籍管理  │  段落定位  │  任务状态  │  笔记对话  │  设置    │
├──────────────────────────────────────────────────────────┤
│                Agent 执行层（OpenAI Agents SDK）           │
│  任务规划  │  工具调用  │  分层生成  │  证据回填  │  校验    │
├──────────────────────────────────────────────────────────┤
│                模型服务（兼容 OpenAI 接口）                 │
│  可配置多模型  │  按任务分配（小模型 / 大模型）            │
└──────────────────────────────────────────────────────────┘
```

### 2.2 关键工程约束

| 约束项 | 说明 |
| :--- | :--- |
| **Server 与 Agent 分离** | Server 拥有业务数据库读写权；Agent 服务只接收任务、模型配置和工具描述，通过带认证的内部回调读取原文、保存结果或校验提交。 |
| **通信方式** | 版本化 HTTP API + SSE 事件流；共享认证令牌。 |
| **权限隔离** | Agent 通过受限工具集访问数据（目录读取、全文检索、段落精读、笔记读取、四层读取、术语表查询、引文核验），工具返回材料自动附带章/段坐标和指纹。 |
| **任务级原文证据索引** | 每次任务执行中，Agent 读取的每一段原文按「章序号 + 段序号」登记到任务级原文证据索引；引文校验以该索引和原文为准，原文变化时通过文本指纹使相关结果失效。 |
| **预算控制** | 每个任务声明请求预算、工具预算、超时限制和共享 Token 预算；运行钩子统计模型请求、工具调用和 Token 用量。 |

## 3. 四层阅读工作空间（核心功能）

四层工作空间对应四种阅读尺度，每层以**任务契约**声明输入范围、输出结构、可用工具、完成条件和预算限制。

### 3.1 全书层（Book Level）

| 属性 | 定义 |
| :--- | :--- |
| **阅读尺度** | 宏观：全书概览 |
| **输入范围** | 目录、章节标题、章节摘要、关键段落 |
| **输出结构** | 全书核心问题、结构地图、论证主线、章节关系图谱、作者知识立场、写作意图、该书在作者及人类知识体系中的地位 |
| **生成时机** | 书籍导入后自动预生成（总量少，阅读前必需） |
| **展示位置** | 右栏「四层笔记」标签页 → 全书层子页 |
| **任务契约** | 校验字段完整性 + 节点覆盖 + 引文逐字匹配 |
| **材料边界** | 上一层的全文不直接进入下一层材料，以控制上下文长度；层间以结构化字段和引用衔接 |

### 3.2 章节层（Chapter Level）

| 属性 | 定义 |
| :--- | :--- |
| **阅读尺度** | 中观：单章论证结构 |
| **输入范围** | 章节标题树、段落导航、上一章交接信息、已有语义层概括 |
| **输出结构** | 章节定位、论证区块划分、转折与承接关系、本章在全书中功能、章内各小节逻辑递进关系 |
| **生成时机** | 书籍导入后自动预生成（复用已有语义层概括生成段落导航，标记尚未生成概括的段落） |
| **展示位置** | 右栏「四层笔记」标签页 → 章节层子页 |
| **任务契约** | 校验节点覆盖 + 字段完整 + 枚举取值 + 字数上限 + 转折点数量 + 引文逐字匹配 |

### 3.3 语义层（Semantic Level）

| 属性 | 定义 |
| :--- | :--- |
| **阅读尺度** | 微观：段落/句子理解 |
| **输入范围** | 目标段、前后段（按标题层级选择覆盖本段且不少于 3 段的窗口，窗口上限 6000 字符，超限时退回本段前后各 2 段）、所属章节结构、已有笔记 |
| **输出结构** | ① 段落要点（简短解释）② 段落详述（意图/定位/作用）③ 逐句说明（字面解释） |
| **生成时机** | 按段预生成（倾向全部预生成，不做灵活解释；灵活提问由对话模块承接） |
| **展示交互** | ① 正文右侧：段落要点（简短解释，常驻显示）<br>② 点击段落下方「详细 / 逐句」按键 → 右栏「四层笔记 → 语义层」展开完整解释（详述 + 逐句说明） |
| **任务契约** | 校验要点/释义/逐句说明的结构正确 + 句数与原文一致 |

### 3.4 概念层（Concept Level）

| 属性 | 定义 |
| :--- | :--- |
| **阅读尺度** | 术语：概念辨析与演化 |
| **输入范围** | 目标句、邻段、语义层参考、已有意义地图 |
| **输出结构** | 义项定义、适用范围、辨析维度、跨章证据、演化链 |
| **生成时机** | 预生成（核心高频术语，数量较少）+ 用户划词触发（弹窗形式） |
| **展示交互** | ① 预生成内容在右栏「四层笔记 → 概念层」子页<br>② 用户划词 → 弹出操作栏（查看概念解释 / 带入对话）→ 弹窗展示概念层解释 |
| **任务契约** | 校验义项 + 范围 + 维度 + 演化链 + 跨章证据 |
| **检索策略** | 先做文本归一化后的精确匹配，复合术语匹配失败时再尝试子词扩展 |

## 4. 智能对话模块

### 4.1 功能定位

独立于四层预生成的**灵活提问通道**，与四层共享同一 Agent 和原文权限，用于承接预生成内容无法覆盖的个性化问题。

### 4.2 核心能力

| 能力 | 说明 |
| :--- | :--- |
| 上下文范围 | 限定在当前书籍范围内回答 |
| 引用选段 | 用户划选原文可直接带入对话 |
| @章节补全 | 可指定引用某章节作为上下文 |
| 流式回答 | 实时显示生成过程（SSE 事件流） |
| 停止 / 重试 | 支持中断生成和重新生成 |
| Markdown 导出 | 对话内容可导出为 Markdown |
| 对话摘记 | 可保存为工作区笔记 |
| 多轮对话 | 按书保存对话历史，支持多轮追问 |

### 4.3 展示位置

右栏「对话」标签页，与「四层笔记」并列切换。

## 5. 前端交互详细规范

### 5.1 整体布局

```
┌──────────┬────────────────────────┬──────────┬──────────────────────┐
│  左栏     │      中栏              │ 正文右侧  │  右栏                 │
│  目录     │      正文              │ 简短解释  │  标签页切换            │
│  导航     │   （按段切分）         │ （常驻）  │  [四层笔记 | 对话]    │
│           │                       │           │                       │
│  ▸ 序言   │   第1段...            │ [要点]    │  四层笔记页：          │
│  ▾ 第一章 │   第2段...            │ [要点]    │  · 全书层             │
│  ▾ 第七章 │     [详细/逐句]按钮   │ [要点]    │  · 章节层             │
│    ▸ 导言│   第3段...            │ [要点]    │  · 语义层（默认）      │
│    ▸ 一   │                       │           │  · 概念层             │
│           │                       │           │                       │
│           │                       │           │  对话页：              │
│           │                       │           │  · 对话历史 + 输入框   │
│           │                       │           │  · 引用选段展示        │
└──────────┴────────────────────────┴──────────┴──────────────────────┘
```

### 5.2 关键交互流程

#### 流程 1：阅读中查看段落解释

1. 用户阅读正文，正文右侧看到每段的简短解释（要点），随原文并排展示。
2. 对某段感兴趣 → 点击该段下方的「详细 / 逐句」按键。
3. 右栏自动切换到「四层笔记 → 语义层」，展示该段的完整解释：
   - **整段详述**：解释该段的意图、定位、作用。
   - **逐句说明**：对应该段每一句的字面解释。
4. 解释中的引文可点击，跳转回原文对应段落（基于章/段坐标）。

#### 流程 2：划词查询概念

1. 用户在正文中划选术语或句子。
2. 弹出操作栏，提供两个选项：
   - **查看概念解释**：弹窗展示概念层解释（义项 / 适用范围 / 辨析维度 / 跨章证据）。
   - **带入对话**：右栏切换到「对话」页，选中文本自动填入输入框作为上下文。
3. 用户可在对话中基于该选段继续提问。

#### 流程 3：书籍导入与预生成

1. 用户通过「导入」按钮导入 EPUB / TXT 文件。
2. 系统执行预处理流水线：
   - 无效内容清洗（去除广告、版权页等）。
   - 提取标题树，建立多级标题的层级结构。
   - 按段切分正文，为每段分配序列 ID，建立「标题树 + 段落序列」定位系统。
   - 结构化数据存入每本书独立的 SQLite 数据库。
3. 后台自动触发分层生成任务：
   - 全书层 → 章节层 → 语义层（按段）→ 概念层（核心词）。
4. 各任务进度在任务面板中显示，支持取消、重试、重启恢复。
5. 生成完成后，各层内容可在右栏对应子页查看；未通过校验的内容不进入读者界面。

#### 流程 4：辅助内容跳转回原文

- 无论在全书层结构地图、章节层论证图谱还是语义层逐句解释中，凡包含原文引用的位置，均支持点击跳转回正文对应段落。
- 目录导航、搜索结果、笔记锚点、对话引用统一使用章/段坐标，实现全应用范围内的位置一致性。

## 6. 数据模型（概要）

### 6.1 核心表结构

| 表名 | 职责 |
| :--- | :--- |
| `book_nodes` | 标题树节点（章/节/小节层级关系、标题文本） |
| `book_paragraphs` | 段落表（章序号、段序号、原文内容、文本指纹） |
| `layer_results` | 四层生成结果（层类型、章/段坐标、结构化 JSON、校验状态、指纹） |
| `agent_notes` | Agent 提交的笔记内容 |
| `workspace_notes` | 用户编辑的工作区笔记 |
| `concept_layer` | 概念层数据（术语、义项、适用范围） |
| `concept_sense` | 概念义项明细 |
| `concept_occurrence` | 概念出现位置（章/段坐标） |
| `reader_state` | 阅读状态与概念地图缓存 |
| `agent_tasks` | 任务记录（状态、预算、事件流、取消标记、重试次数） |

### 6.2 文本坐标系统

所有功能共用统一的**章/段坐标 + 文本指纹**：

| 功能 | 坐标用法 |
| :--- | :--- |
| 目录导航 | 定位到章（章序号） |
| 段落旁注 | 绑定段坐标（章序号 + 段序号） |
| 对话引用 | 携带章/段范围 |
| 笔记锚点 | 指向具体段落 |
| Agent 证据索引 | 按章序号 + 段序号登记每次读取的原文片段 |
| 引文校验 | 以证据索引和原文为准，逐字匹配 |

## 7. 任务执行与校验机制

### 7.1 任务生命周期

```
Server 创建任务记录
  → 固化章/段坐标、原文指纹和已有笔记
  → Agent 组装任务材料并加载允许使用的工具
  → 模型循环：
      每轮调用一个工具
      → 读取的原文按章/段登记到原文证据索引
  → 模型通过「提交工具」提交结构化结果
  → 校验器检查：
      字段完整性 / 节点覆盖 / 引文逐字匹配 / 指纹一致
  → 通过 → 写入笔记与分层结果 → 通过事件流回传「完成」状态
  → 失败 → 将错误退回模型修改 → 重新提交（最多 N 次）
  → 取消 / 超时 / 预算耗尽 → 保留已有状态 → 支持恢复与复现
```

**补充说明：**
- 提交工具作为终止工具，校验器通过即结束任务。
- L3（语义层）生成与修订复用同一会话；独立校验使用单独会话。
- 任务取消、超时和预算耗尽统一归一为可处理的终止状态。
- 事件流记录模型调用、工具调用、材料读取和校验结果，使长任务可以恢复、复现和比较。

### 7.2 校验维度

| 层级 | 校验项 |
| :--- | :--- |
| **全书层** | 字段完整、节点覆盖、引文逐字匹配 |
| **章节层** | 节点覆盖、字段完整、枚举取值、字数上限、转折点数量、引文逐字匹配 |
| **语义层** | 要点/释义/逐句说明结构正确、句数与原文一致 |
| **概念层** | 义项、适用范围、维度、演化链、跨章证据完整 |
| **通用** | 文本指纹一致、层间引用可追溯、无重复生成 |

**质量维度总览：** 结构完整性、证据可回溯性、定位准确性、层间一致性、重复运行稳定性、阅读效果。

## 8. 设置与配置

| 配置项 | 说明 |
| :--- | :--- |
| **模型 API 接入** | 用户在设置页自行配置兼容 OpenAI 接口的模型服务地址、API 密钥、模型名称 |
| **模型分配策略** | 抽取、分类、摘要等低成本环节 → 较小模型；分层生成和复杂修订 → 能力更强的模型 |
| **任务预算** | 请求数上限、工具调用数上限、总时限、共享 Token 预算 |
| **隐私提示** | 明确告知用户：书籍内容将被发送至所选第三方大模型 API 进行处理；提供隐私协议说明 |
| **技能加载** | 技能按需加载，未加载的技能不占用工具列表和调用预算 |

---

## 9. 非功能性需求

| 维度 | 要求 |
| :--- | :--- |
| **性能** | 预生成任务后台静默执行，不阻塞用户阅读；语义层简短解释应在页面加载时即时展示；任务面板支持进度展示 |
| **稳定性** | 任务支持取消、超时、重试、中断恢复；Agent 崩溃不影响 Server 数据完整性；长任务状态可持久化 |
| **可替换性** | 模型服务可独立替换；Agent 框架可升级（当前基于 OpenAI Agents SDK）；不改变任务契约和校验规则的前提下可评估新策略 |
| **数据安全** | Agent 不直接访问业务数据库；所有跨服务通信携带认证令牌；用户 API Key 加密存储 |
| **可扩展性** | 定位系统与存储结构支持后续接入更多书籍格式（PDF / EPUB 等）；每本书独立 SQLite 数据库 |
| **可复现性** | 运行记录完整保存，单次生成结果不作为质量结论，以可复现的运行记录为基础进行评估 |

## 10. 后续迭代方向

1. **社区共享：** 用户生成的优质注释 / 笔记可否跨用户共享、复用。
2. **多格式支持：** 扩展 PDF 解析与 OCR 能力，支持扫描件。
3. **协作阅读：** 多人共读同一本书，共享任务结果与笔记。
4. **教学集成：** 与课程管理系统对接，教师可布置阅读任务、查看学生笔记；结合课程或读书会试点。
5. **个性化适配：** 根据用户知识背景调整解释的详略程度与深浅。
6. **知识图谱可视化：** 将全书层 / 章节层的论证结构以可视化图谱方式呈现。
7. **模型微调与压缩：** 评估领域微调、提示词模板和上下文压缩策略的适用条件。
