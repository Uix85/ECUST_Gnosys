# 项目各层级分类说明文档

> 版本：v1  
> 用途：说明系统结构图中 Agent、Server、Frontend 三层的划分依据，以及各层大类、小类的职责与作用范围。  
> 配套图：`docs/项目横向纵向展示图.drawio`  
> 约定：`全五` = L1、L2、L3、L4、Chat；`L1–L4` = 四个阅读层；`Chat` = 对话。

---

## 1. 分类原则

1. **按职责边界分类，不按代码目录分类。**  
   一个大类下的各小类共享同一类职责；不同大类之间不混放。

2. **按数据/流程的生命周期分类。**  
   内容基座、阅读中产生的数据、服务配置，生命周期不同，分开放。

3. **用户可见模块与内部机制分开。**  
   读者直接使用的界面、后台自动运行并用于支撑生成的机制，不放在同一层级。

4. **已移除“任务与待核稿”模块。**  
   四层内容直接生成、自动校验后进入阅读界面；读者不再经过任务/待核阶段。Agent 的 Loop、预算、校验仍在后台运行，但不形成前端任务模块。

5. **每层标注作用范围。**  
   大类和小类都说明作用于 L1–L4、Chat 中的哪些方面，避免把所有能力都写成“五层通用”。

---

## 2. Agent 智能体

Agent 是执行核心。它接收一层阅读任务，读取材料，调用工具，生成辅助内容，经过证据与质量校验后提交给 Server。

### 2.1 大类与小类

| 大类 | 小类 | 职责 | 作用范围 |
|---|---|---|---|
| **基础运行** | 模型配置与成本分配 | 选择模型、配置参数、统计成本 | 全五 |
|  | 预算与终止机制 | 控制请求、工具、时间和成本，定义停止条件 | 全五 |
|  | 权限边界与安全机制 | 工具白名单、层写权限、指令注入防护、单书边界 | 全五 |
|  | Loop 循环规则 | 模型—工具—观察—提交的执行循环 | 全五 |
| **工具与技能** | 目录读取 | 读取章节目录与结构 | 全五；L1、L2、Chat 主用 |
|  | 原文定位检索 | 检索原文并返回章/段位置 | 全五 |
|  | 原文细节读取 | 精读段落、批量读取、按节点读取 | L2–L4、Chat 主用；L1 可选 |
|  | 辅助内容读取 | 读取已有四层成果、笔记、术语规范 | 全五（Chat 只读） |
|  | 交卷工具 | 提交结构化结果并触发校验 | L1–L4 |
|  | 辅助阅读技能 | 阅读、检索、精读、引文核验的操作规程 | L1–L4（L1、L2 目标态） |
|  | 对话技能 | 对话检索、引用和回答的操作规程 | Chat |
| **生成前提** | 辅助阅读任务契约 | 声明每层任务的输入范围、输出结构、工具、校验和预算 | L1–L4 |
|  | 上下文组装 | 选择、排序、打包本次生成所需材料 | 全五 |
| **质量控制** | 任务证据记录 | 记录当前任务实际读过的原文片段，供引文核验 | 全五 |
|  | 引文核验 | 检查引文是否逐字出现在任务证据记录中 | 全五 |
|  | 生成内容复核 | 对候选内容做内容层复核 | L1–L4 |
|  | 自动校验/退回修订 | 校验失败时退回模型修订或自动校验 | L1–L4 |
|  | 独立校验机制 | 独立于生成会话的结构、证据和字段校验 | L1–L4 |
| **记忆机制** | 记忆机制 | 跨任务、跨层的上下文记忆（拟建） | 全五（拟建） |

### 2.2 为什么这样划分

- **基础运行**：模型、预算、权限、Loop 是跨任务共享的运行底座。它们不随 L1–L4 的任务内容变化，因此合并为一个大类。  
  这些机制只在后台运行，不形成前端的任务/待核模块。

- **工具与技能**：工具是 Agent 能执行的动作；技能是使用工具的操作规程。两者都直接扩展 Agent 的行动能力，因此放在一起。  
  交卷工具属于工具；“生成内容复核”“独立校验机制”放在质量控制，不混入工具组。

- **生成前提**：任务契约规定“生成什么、输出什么、怎么校验”；上下文组装规定“这次拿什么材料”。两者都发生在生成之前，因此归入“生成前提”。  
  任务契约是内部配置，不是用户可见的任务模块。

- **质量控制**：任务证据记录、引文核验、内容复核、自动校验/退回修订、独立校验都属于生成后的质量闭环，因此独立成类。

- **记忆机制**：记忆跨任务、跨层提供上下文，不属于某一次生成的输入或某一步质量控制，因此单独成类；当前为拟建能力。

### 2.3 绘制约定

- 图中“目录读取”出现两次，按一个工具处理，不重复绘制。
- “辅助阅读技能”和“对话技能”作为技能项，与工具项区分颜色。
- “记忆机制”可留空框或虚线框，表示拟建。
- “基础运行”和“质量控制”是后台机制，不与前端任务面板对应。

## 3. Server 服务器

Server 管理数据、配置和接口。它不直接生成内容，但为 Agent 和 Frontend 提供原文、成果、对话、配置和回调。

### 3.1 大类与小类

| 大类 | 小类 | 职责 | 作用范围 |
|---|---|---|---|
| **内容基座** | 导入与预处理 | EPUB/TXT 接入、清洗、标题树、段落切分 | 全五（前置） |
|  | 文本数据存储结构 | 书籍、章节、标题节点、段落、文本指纹 | 全五 |
|  | 定位系统与索引机制 | 章/段定位、锚点、全文索引、术语索引 | 全五（L1、L2 主要用结构；L3、L4、Chat 主要用寻址/引用） |
| **辅助阅读** | 辅助内容读取 | 读取四层成果、笔记、概念 | 全五（Chat 只读） |
|  | 辅助内容存储与修改 | 写入、修改四层成果和笔记 | L1–L4 |
|  | 对话记录 | 保存对话会话、消息、引用和事件 | Chat |
| **服务配置** | 模型设置与配置 | 模型地址、密钥、参数、预算等设置 | 全五（全局） |
|  | API / SSE | 前端与 Server 的请求、事件流 | 全五 |
|  | 工具回调 | Agent 工具调用回到 Server 执行 | 全五 |

### 3.2 为什么这样划分

- **内容基座**：导入、原文结构、定位索引都由原文派生，是所有阅读层和对话共用的输入底座，生命周期稳定，因此放在一起。

- **辅助阅读**：辅助内容读取、存储与修改、对话记录，都是阅读过程中产生、按书保存、可被前端读取的数据。它们属于同一类“阅读生成数据”，因此放在一起。  
  “读取”和“存储与修改”是同一数据对象的读/写两个方向，不是两类数据。

- **服务配置**：模型设置、API/SSE、工具回调都不是阅读内容或阅读数据，而是服务运行所需的配置和通信边界，因此独立成类。  
  这样配置不再和业务数据混在一起。

### 3.3 绘制约定

- “辅助内容读取”和“辅助内容存储与修改”可画成同一数据条目的读/写两端。
- “对话记录”只服务 Chat，不与四层成果混为同一小类。
- “服务配置”包含模型设置和通信接口，不再叫“业务数据与配置”。

---

## 4. Frontend 前端

Frontend 面向读者，负责阅读界面、辅助内容展示和全局设置。它不直接生成内容，也不直接访问数据库。

### 4.1 大类与小类

| 大类 | 小类 | 职责 | 作用范围 |
|---|---|---|---|
| **阅读平台** | 书库与导入口 | 书库、导入、删除、书籍入口 | 全五（入口） |
|  | 基础阅读与交互行为 | 正文、目录、搜索、书签、排版、翻页、锚点 | 全五 |
|  | 原文交互 | 划词、引用、来源跳转、保存笔记 | 全五（L3、L4、Chat 主用；来源跳转全五） |
| **辅助阅读** | 辅助阅读展示 | 四层辅助内容、段落旁注、概念卡、引用展示 | L1–L4 |
|  | 对话窗口 | 问答、流式回答、引用、会话入口 | Chat |
| **设置** | 模型 / API | 模型服务地址、密钥、模型名称 | 全五（全局） |
|  | 界面偏好 | 字号、行距、布局、主题等 | 全五（全局） |

### 4.2 为什么这样划分

- **阅读平台**：书库、正文阅读、导航、原文交互都不依赖 AI 生成结果，是读者进入文本和操作原文的基础界面，因此放在一起。

- **辅助阅读**：四层辅助内容展示和对话窗口都依赖生成结果，是读者消费 AI 辅助内容的面，因此放在一起。  
  “辅助阅读展示”对应 L1–L4；“对话窗口”对应 Chat。

- **设置**：模型/API 和界面偏好都是全局设置，不随单本书或单次阅读变化，因此独立成类。

### 4.3 绘制约定

- “任务与待核稿”不再出现在前端分类中。
- “对话窗口”可保留为辅助阅读的小类；如果后续确认删除对话框，去掉这一小类即可，Chat 列仍用于说明其他层的作用范围。
- “模型 / API”和“界面偏好”都放在“设置”大类下。

## 5. 纵向四层任务

| 层级 | 定义 | 目标（操作化） | 意义 | 输出 |
|---|---|---|---|---|
| **L1 全书层** | 以整本书为阅读单位，构建全书问题意识、结构地图、论证主线以及章节关系等宏观阅读任务。 | 读者在进入正文前，能借全书层把握全书的核心论证问题、总体结构和论证走向，从而判断各章在全书中的位置和阅读顺序，并能带着全书框架进入后续阅读。 | 把长篇文本压缩成可携带的总体框架，降低全书认知负荷，为章节、语义、概念层提供全局约束。 | 全书概览、核心问题、结构地图、论证主线、章节关系。 |
| **L2 章节层** | 以章为阅读单位，梳理本章论证逻辑、各部分在整体中的功能以及章际承接关系等章节级任务。 | 读者在进入一章前，能借章节层把握本章的总体论证结构，知道各部分在章内的位置和推进关系，从而按结构定位到具体部分，带着论证框架进入段落细读。 | 把章内分散内容组织成可携带的认知结构，减少阅读中临时拼接，承接全书宏观与段落微观。 | 章节定位、总体结构、论证链条、部分作用、承上启下、原文证据。 |
| **L3 语义层** | 以段落或句子为解释单元，处理具体语义、句段关系、上下文指代以及原文引用等微观阅读任务。 | 读者在读到具体段落或句子时，能借语义层把握该段或句的字面意思、语义逻辑、指代和上下文如何限定含义，从而降低逐句理解门槛，并能顺着解释回到原文继续细读。 | 具体语义是阅读落地的最小单位；降低逐句细读门槛，为章节层提供段落材料，为概念层提供语境参考。 | 要点、释义、知识补充、上下文说明、原文引用。 |
| **L4 概念层** | 以概念、术语或词汇为解释单元，处理定义、义项、辨析、概念关系以及文本证据等概念层任务。 | 读者在遇到术语时，能借概念层把握该术语在当前语境下的读法、它与日常义及其他义项的区别、以及概念之间的关系，从而避免一词一义误读，并能带着概念区分继续阅读。 | 哲学社会科学文本概念密度高，术语多义和译名差异容易造成理解偏差；概念层保证跨章理解一致，支撑概念辨析和概念转变。 | 定义、义项辨析、概念关系、原文证据。 |

> 图中 L2 的“意义”栏目前写的是目标句，容易和目标重复；本文档按“意义”口径改为“把章内分散内容组织成可携带的认知结构……”。图中可同步替换。

## 6. 任务与待核稿的移除说明

后续系统不再保留“任务与待核稿”模块：

- 四层内容由后台自动生成、自动校验，通过后直接进入阅读界面；
- 对话直接回答，不进入任务/待核流程；
- Frontend 不再设置任务/运行大类；
- Server 不再列任务/待核记录；
- Agent 的 Loop、预算、终止、质量控制仍在后台运行，但不形成用户可见的任务模块。

## 7. 维护约定

- 本文件与 `docs/项目横向纵向展示图.drawio` 配套使用；图中每个大类对应本文档的一节。
- 修改图上的大类或小类名称时，同步修改本文件及申报书中的对应表述。
- 新增能力时，先判断其职责属于哪个大类，再补充小类和作用范围。
