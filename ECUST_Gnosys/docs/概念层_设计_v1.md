# 概念层（L4）设计 v1

本文是 `概念层_需求_v1.md` 的实现设计。**v1.1 修订**：吸收了对 scope 分类、
定义段落检索、性能与交互的一轮批评，并含作者自审。

---

## 0. 本轮修订（先看这个）

| # | 问题 | 判断 |
|---|---|---|
| 1 | `find_definition_passages` 只看含该词的段落 | **必须改**：作者解释某概念时不一定再写那个词，邻近段落是主要来源 → 改为**窗口扫描** |
| 2 | 检索定义段之前要先知道词义是否统一 | **必须改**：这是依赖顺序问题，且实测该词可能出现在 370 段 → 工具改为先给**分布概览** |
| 3 | `scope` 里混进了 `shifting` | **设计错误，必须改**：范围与稳定性是**正交**两维，`shifting` 不是范围 |
| 4 | 词义不稳定时怎么找原文解释 | 随 2/3 解决：**按簇找**，簇边界优先在章首/转折处 |
| 5 | 书内无解释、只当通行术语用的情况 | **必须加**：`has_definition` 由布尔改**三值** |
| 6 | 作者本身用错了术语，要不要找误用证据 | **v1 不做**，但加 `author_stipulation` 记录"作者自定用法"；判"对错"需要外部标准，与"只用本书原文"红线冲突 |

### 自审发现的问题（我自己批）

7. **性能**：朴素全扫一次 1.11s，且 `logical_paragraphs` 每次调用都重新解析 HTML（第二次全扫 0.42s 全是解析）→ 需要按需扫描 + 结果缓存。
8. **样本偏差**：某词出现 370 段，我的"返回 20 条"会按章序截断，给出**有偏样本**去判"是否全书一致" → 必须改成分布 + 抽样。
9. **候选提取太弱**：只按标点切分，遇到无标点的长片段（"必须加以较确切的规定"）只剩 reject → 需要术语表反向匹配 + 窗口取子串。
10. **停用词表含单字**（我/他/这）→「自我」「他者」会被算命中；虽然 ≥3 才算句子，阈值很窄，必须用黄金用例回归调参。
11. **L3 内容不及格的既知事实没体现**：`locate_term_context` 返回的 semantic 可能被模型当依据 → 规程必须写明"L3 是参考，不是依据"。
12. **缓存流程没写清**：用户给的是 `(term, 位置)`，而义项键是 `(term_norm, sense_idx)` → 必须先按位置查 occurrence 定位义项，否则同一义项会被重复生成。
13. **`confusion_type` 应多值**：一个词可同时是译名问题 + 日常义偏移。
14. **交互缺口**：全扫 1.1s + 模型 4~6 步 ≈ 30~60s，而读者在等 → 必须"先回执、后推送"，或用廉价卡片先占位。
15. **没有回归集**：validator 里"book 需两处证据"这类规则没有黄金用例就无法调参。

## 1. 实测数据（决策依据）

**术语长度**（三本书正文统计）：

| 类型 | 最长实例 | 长度 |
|---|---|---|
| 真实术语 | 费希特和谢林的体系之差异 | 12 |
| 书名（书名号内） | 耶拿时期的逻辑学、形而上学和自然哲学 | 17 |
| 句子片段 | 我与对象无差别的感性确定性的直接… | 16+ |

→ 术语阈值 **12**；超长不直接拒绝，走"候选 + 用户确认"。书源里还混有盗版站广告文本（"为了方便书友朋友找书和看书"），拦截层顺带挡掉。

**性能与分布**（《精神现象学》）：

- 朴素全扫 9 章 = **1.11s**；重复全扫 0.42s（全部是 HTML 重新解析）
- 「对象」出现在 **370 段**，按章分布 `{0:37, 1:15, 2:12, 3:18, 4:38, 5:71, 6:102, 7:58, 8:19}`

→ 两个结论：① 全扫要缓存，不能每次划词都做；② 370 条不可能全看，工具必须给**分布**。

## 2. 适用范围：正交两维（修订核心）

原设计把 `book/chapter/sentence/shifting` 并列，是错的。正确模型：

```
维度一：义项数量        1 个 还是 N 个
维度二：每个义项的范围  全书 / 某章 / 某段句
演化(shifting) = N 个义项，且按文本顺序推进（不是第三种范围）
```

所以输出结构从"一个 scope 字段"改成 **`senses[]` 数组**：

```jsonc
{
  "has_definition": "explicit",          // explicit=书中给出定义 / inferred=从使用中归纳 / external=当通行术语用
  "definition_note": "第 3 章第 12 段给出规定：…",
  "confusion_types": ["translation", "idiom_shift"],
  "senses": [
    {
      "reading": "这一句里的「对象」指意识所面对的、被规定的那个东西",
      "common_reading": "日常语言里指客观事物、目标",
      "scope": "chapter",                // book / chapter / paragraph
      "range_note": "自第 2 章起，至第 4 章前",
      "chapter_range": [2, 3],
      "evolves_to_next": true,           // 是否演化到下一个义项
      "evidence": [
        {"chapter_idx": 2, "paragraph_index": 7, "quote": "…"},
        {"chapter_idx": 3, "paragraph_index": 20, "quote": "…"}
      ]
    },
    { "scope": "book", "evolves_to_next": false, "evidence": [ … ] }
  ],
  "quotes": ["…"]
}
```

**为什么这样更好**：① 一个词可以同时有"第 2–3 章一个意思、第 5 章起另一个意思"；② `book` 不再是"和 shifting 并列的选项"，而是**某个义项**的范围；③ 演化用 `evolves_to_next` 链表达，能表达多段演化而不只是一个布尔。

## 3. 输入拦截（修订版）

`backend/selection_gate.py`，纯本地。三层对齐 + 候选回退；本轮修订：候选提取增强、停用词表收紧。

```python
MAX_TERM_CHARS = 12
MIN_OCCURRENCES = 2
BOUNDARY = "，。、；：？！“”‘’《》〈〉（）【】〔〕…—·,.;:?!\"'()[]{}<> \t\n"
# 单字停用词只用于"整串都是虚词"的判定；句子判定改用长度 + 标点 + 虚词密度三合一
STOPWORDS = frozenset("的了是在和与就也都而及其之有着过把被给对从向为以于")
ALL_STOPWORDS = STOPWORDS | frozenset("我你他她它这那")


def _candidates(raw: str, glossary: dict[str, str] | None = None) -> tuple[str, ...]:
    """划多了时的候选：① 术语表反向匹配 ② 标点切分 ③ 滑动窗口取 ≤12 字子串。"""
    if glossary:
        hits = [t for t in glossary if t in raw]
        if hits:
            return tuple(sorted(hits, key=len, reverse=True))[:3]
    parts = [p.strip(BOUNDARY) for p in re.split(r"[、，,／/；;]", raw)]
    parts = [p for p in parts if p and len(p) <= MAX_TERM_CHARS]
    if parts:
        return tuple(parts)[:3]
    # 无标点的长片段：从两端收缩到 ≤12 字，取中间一段
    if len(raw) > MAX_TERM_CHARS:
        return (raw[:MAX_TERM_CHARS], raw[-MAX_TERM_CHARS:])
    return ()


def _looks_like_sentence(s: str) -> bool:
    if re.search(r"[。！？!?；;]", s):
        return True                                   # 有句末标点 = 句子
    if len(s) <= MAX_TERM_CHARS:
        return False                                  # 短串一律当术语候选
    stop = sum(1 for ch in s if ch in ALL_STOPWORDS)
    return stop >= 3 or stop / len(s) > 0.25          # 虚词扎堆
```

其余（`locate` / `_strip` / `gate`）与前一版一致：三层对齐拿到**原文片段**当 term，`corrected` 时告知读者，超长给候选让用户换。

## 4. 工具（修订版）

### 4.1 `find_term_occurrences` → 改为**分布 + 抽样**

```python
async def find_term_occurrences(args):
    """先给分布概览，再给抽样上下文。370 条不可能全给，按章序截断会有偏。"""
    term = (args.get("term") or "").strip()
    limit = args.get("limit", 12)                     # 抽样上限
    needle = normalize_text(term)
    per_chapter, samples = [], []
    for ci in range(len(_chapters(book_id))):
        _, paragraphs, _ = logical_paragraphs(book_id, ci)
        hits = [p for p in paragraphs if needle and needle in normalize_text(p["text"])]
        if not hits:
            continue
        per_chapter.append({"chapter_idx": ci, "count": len(hits)})
        step = max(1, len(hits) // 3)                 # 每章最多抽 3 段，均匀取样
        for p in hits[::step][:3]:
            if len(samples) >= limit:
                break
            ledger.setdefault((ci, p["paragraph_index"]), []).append(p["text"])
            samples.append({"material_type": "original_text",
                            "reference": {"chapter_idx": ci, "paragraph_index": p["paragraph_index"],
                                          "fingerprint": p["fingerprint"]},
                            "snippet": p["text"][:400]})
    return {"total": sum(c["count"] for c in per_chapter),
            "distribution": per_chapter, "samples": samples}
```

**关键效果**：模型第一眼看到的是"哪些章密集、哪些章稀疏"——这才是判"是否全书一致"的依据，而不是二十条连续的片段。

### 4.2 `find_definition_passages` → 窗口扫描 + 加权

```python
DEFINITION_ANCHORS = ("意味着", "指的是", "称为", "叫做", "这就是说", "所谓",
                      "意思是", "定义为", "就其本身而言", "在这个意义上")
# 作者换用法时常用的转折语 —— 义项分界的高发位置
PIVOT_WORDS = ("然而", "但是", "其实", "更确切地说", "毋宁说", "严格说来", "相反地")


async def find_definition_passages(args):
    """扫描 [出现段落 ± window] 的窗口，因为作者解释某概念时不一定再写那个词。"""
    term = (args.get("term") or "").strip()
    window = args.get("window", 1)
    lo, hi = (args.get("chapter_range") or [0, len(_chapters(book_id)) - 1])
    scored = []
    for ci in range(lo, hi + 1):
        _, paragraphs, _ = logical_paragraphs(book_id, ci)
        seeds = [p["paragraph_index"] for p in paragraphs if term in p["text"]]
        window_idx = {i for s in seeds for i in range(s - window, s + window + 1)
                      if 0 <= i < len(paragraphs)}
        for i in sorted(window_idx):
            text = paragraphs[i]["text"]
            score = sum(1 for a in DEFINITION_ANCHORS if a in text)
            score += 2 * sum(1 for w in PIVOT_WORDS if w in text)     # 转折处更容易重新定义
            score += 1 if i <= 2 else 0                               # 章首
            score += 1 if term in text else 0                         # 含该词本身
            if score:
                scored.append((score, ci, i, text))
    scored.sort(key=lambda x: -x[0])
    out = []
    for score, ci, i, text in scored[:args.get("limit", 6)]:
        ledger.setdefault((ci, i), []).append(text)
        out.append({"score": score, "chapter_idx": ci,
                    "reference": {"chapter_idx": ci, "paragraph_index": i,
                                  "fingerprint": fingerprint(text)},
                    "text": text[:600]})
    return {"candidates": out}
```

**配合的判定顺序**（写进规程，解决“先看词义是否统一”，v1.2 按读者意见修订）：

```
1) locate_term_context(term, ci, pi, window=1)   # 先就近：本段 + 上下 1 段原文，全部进账本（零额外往返）
2) find_term_occurrences                         # 分布：判是否分簇、是否全书一致
3) 按第 2 步结论定检索范围（检索范围由一致性结论决定，不一律全书搜）：
   - 就近段落里已有定义 → 直接采用，不再检全局
   - 全书一致 → find_definition_passages(term)
   - 仅单章一致 → find_definition_passages(term, chapter_range=[该章])
4) 代回测试：把 A 簇读法代回 B 簇句子 → 见第 9 节三档表
```

### 4.3 `locate_term_context`（不变，但规程里降级 L3 的地位）

## 5. 终止标准（validator，修订版）

```python
DEF_KINDS = ("explicit", "inferred", "external")
SCOPES = ("book", "chapter", "paragraph")
CONFUSIONS = ("translation", "idiom_shift", "anachronism", "author_reversal",
              "author_stipulation")     # 作者自定用法（不判对错，只标注）


def validate_concept(args, sources: list[str], book_id: str) -> dict:
    if not args.get("senses"):
        raise ValueError("senses 不能为空")
    if args["has_definition"] not in DEF_KINDS:
        raise ValueError("has_definition 必须是 explicit / inferred / external")
    if args["has_definition"] == "explicit" and not args["definition_note"].strip():
        raise ValueError("声称书中有明确定义时，必须用 definition_note 指出定义内容与位置")
    if not args["confusion_types"] or any(c not in CONFUSIONS for c in args["confusion_types"]):
        raise ValueError("confusion_types 必须是合法枚举且至少一项")

    ends = 0
    for i, sense in enumerate(args["senses"]):
        if not sense["reading"].strip() or not sense["common_reading"].strip():
            raise ValueError(f"第 {i+1} 个义项的 reading 和 common_reading 都不能为空")
        if len(sense["reading"]) > READING_MAX:
            raise ValueError(f"第 {i+1} 个义项的 reading 超过 {READING_MAX} 字上限")
        if sense["scope"] not in SCOPES:
            raise ValueError(f"第 {i+1} 个义项的 scope 必须是 {'/'.join(SCOPES)}")
        if sense["scope"] != "book" and not sense["range_note"].strip():
            raise ValueError(f"第 {i+1} 个义项范围不是全书时，必须用 range_note 说明它管到哪")
        ev = sense.get("evidence") or []
        if not ev:
            raise ValueError(f"第 {i+1} 个义项必须给出原文证据")
        chapters = set()
        for e in ev:
            _check_position(book_id, e["chapter_idx"], e["paragraph_index"])
            _check_quote(e["quote"], sources)
            chapters.add(e["chapter_idx"])
        # 反偷懒：声称全书一致的义项，必须跨章两处证据
        if sense["scope"] == "book" and len(chapters) < 2:
            raise ValueError(f"第 {i+1} 个义项要判全书一致，必须给出跨两章的引文证据；"
                             "证据不足请改判 chapter 或 paragraph")
        if not sense["evolves_to_next"]:
            ends += 1

    if len(args["senses"]) > 1:
        if ends != 1:
            raise ValueError("多个义项时，演化链只能有一个终点（最后一个义项的 evolves_to_next=false）")
        if not all(s["range_note"].strip() for s in args["senses"]):
            raise ValueError("多个义项时，每个义项都要说明它管到哪一节")
    for q in args["quotes"]:
        _check_quote(q, sources)
    return args
```

规则要点：
- **`book` 需要跨章两处证据**（同一章两段不算）——防"省事伪装成全局一致"
- **多义时演化链只能有一个终点**——防义项顺序错乱
- **多义时每个义项都要给范围**——解决你说的"词义不稳定时怎么划定范围"
- 引文一律只认材料账本

## 6. 数据层

```sql
-- 义项：一个词一条或多条
CREATE TABLE IF NOT EXISTS concept_sense (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    book_id INTEGER NOT NULL,
    term TEXT NOT NULL,              -- 原文词形（以原文为准）
    term_norm TEXT NOT NULL,         -- 规范化键（缓存键）
    sense_idx INTEGER NOT NULL,      -- 义项序号，按首现位置排序（稳定，不随重跑变）
    has_definition TEXT NOT NULL,
    definition_note TEXT,
    confusion_types TEXT,            -- JSON 数组
    reading TEXT, common_reading TEXT,
    scope TEXT NOT NULL, range_note TEXT, chapter_range TEXT,
    evolves_to_next INTEGER NOT NULL DEFAULT 0,
    created_at TEXT, updated_at TEXT,
    UNIQUE(book_id, term_norm, sense_idx)
);

-- 义项的成立位置（逻辑坐标，与 L3 一致）
CREATE TABLE IF NOT EXISTS concept_occurrence (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sense_id INTEGER NOT NULL REFERENCES concept_sense(id),
    chapter_idx INTEGER NOT NULL, paragraph_index INTEGER NOT NULL,
    sentence_index INTEGER, fingerprint TEXT, quote TEXT
);
```

**处置**：删掉 `concept_occurrences`（物理坐标，实测 1/38 对不上）；删 `save_concept` 的占位逻辑；清 26 条污染。

**按需扫描缓存**（解决性能，不用建全量倒排索引）：

```sql
CREATE TABLE IF NOT EXISTS term_scan (
    book_id INTEGER NOT NULL, term_norm TEXT NOT NULL,
    total INTEGER NOT NULL, distribution_json TEXT NOT NULL, built_at TEXT NOT NULL,
    PRIMARY KEY (book_id, term_norm)
);
```

首次扫一个词 1.1s，之后命中缓存 ~0ms。若以后发现扫描成为热点，再升级为全量倒排索引（`term_norm → 位置`），现在不做。

## 7. 请求流程与缓存（补上第 12 条缺口）

```
POST /api/layer/concept_explain/{book_id}  {term, chapter_idx, paragraph_index, offset}

1. gate(term, 该段原文)                        # 本地，立即
   → reject：直接返回失败用语（不发请求）
   → corrected：返回 term + 候选，等用户确认（可撤销）
2. 查 concept_sense by term_norm（缓存）        # 本地
   命中且该位置已有 occurrence → 直接返回该义项
   命中但该位置未覆盖 → 先返回该义项 + 标记「该处尚未校验」，后台补跑
   未命中 → 跑 agent
3. run_task(concept_spec)  预算：请求 ≤5 次、工具 ≤6 次、总时限 90s
4. 落库 concept_sense + concept_occurrence，返回
```

**交互缺口（第 14 条）**：30~60s 对"划一下就要看"太重。建议：第 1 步后**立刻返回一张廉价卡片**（词形、出现次数、分布、"正在生成解释…"），结果用 SSE 推送补进弹窗。SSE 机制 L3 已有，直接复用。

## 9. 维度与侧重（v1.2：本轮最重要的补充）

### 9.1 三件事必须分开，否则会把多维度误判成多义

| 层 | 含义 | 例子（齐美尔的「距离」） |
|---|---|---|
| **义项 sense** | 含义不同的单元 | 「距离」作为社会形式 —— 只有一个义项 |
| **维度 dimension** | 同一义项内部的构成面 | 空间距离 / 社会距离 / 心理距离 / 审美距离 |
| **侧重 emphasis** | 某一次使用中凸显的那一面 | 此处讲艺术风格 → 侧重审美维度 |

**不分开的后果很严重**：模型会把齐美尔的「距离」拆成几个义项，而 validator 里
「多义必须给分界范围」那条会把这个错误**确认下来**。这是本设计最容易出错的失败模式。

### 9.2 代回测试升级为三档

| 代回结果 | 结论 |
|---|---|
| 成立且不矛盾 | 同一义项、同一维度（侧重可能不同） |
| 不成立，但不矛盾，换个角度就通 | **同一义项、不同维度**（不得拆成新义项） |
| 不成立且互相矛盾 | 新义项 |

### 9.3 侧重：默认沉默 + 四道门槛

原则上**不写侧重**（读者观察得对：语境内的用词几乎都有一定侧重，全写等于噪声）。
只有满足下列任一条才写，且必须给出 `reason_kind`：

| 门槛 | 说明 | 可客观校验 |
|---|---|---|
| `explicit_marker` | 作者在此处用了元语言标记（“在这个意义上”“就其形式而言”“这里所谓的…不是…”） | **完全可校验**：必须引出该标记原文 |
| `misreading_risk` | 不指出会被读成另一个维度 | 不可自动校验（靠复核/抽检） |
| `minority_usage` | 此处的侧重与全书分布明显不同 | 部分可校验：必须给出对照位置的引文 |
| `argumentative_need` | 该句的论点靠这个维度成立 | 不可自动校验 |

把主观判断里的可核部分榨出来了：`explicit_marker` 和 `minority_usage` 都能进 validator，
剩下的两条诚实标注为“需人工复核”，不假装能自动判。

### 9.4 关于「交给语义层承担语境强调」这个选项

两种做法职责不同、并不冲突：L3 解释**整段怎么读**，L4 解释**这个词在这里怎么读**。
但有两个限制必须记下：

1. **硬前提**：这个选项假设 L3 已经承担了语境强调 —— 而 **L3 内容目前不及格**，
   前提不成立。在 L3 重跑合格之前，L4 必须自己覆盖门槛内的侧重。
2. **即使 L3 合格也要管最小范围**：概念层是读者**主动划词提问**，“这个词在这儿什么意思”
   如果答案不交代关键侧重，等于没回答他的问题。所以 `explicit_marker` 与
   `misreading_risk` 两类至少要能给出。

### 9.5 schema 增补

```jsonc
"senses": [{
  "reading": "…", "common_reading": "…", "scope": "book", "range_note": "",
  "evidence": [ … ],
  "dimensions": [                                  // 可选：同一义项内部的面
     {"name": "空间距离", "note": "与他人/物的空间隔开"},
     {"name": "审美距离", "note": "形式与内容之间的张力"}
  ],
  "emphasis_here": {                               // 可选：默认沉默
     "dimension": "审美距离",
     "why": "本节论艺术风格；不指出会读成空间距离",
     "reason_kind": "explicit_marker",
     "evidence": [{"chapter_idx": 5, "paragraph_index": 3, "quote": "在这个意义上…"}]
  },
  "evolves_to_next": false,
  "distinction_note": ""                           // 多义时必填：为何是不同含义而非不同维度
}]
```

**长度约束**：`dimensions[].name` ≤ 10 字、`emphasis_here.why` ≤ 60 字 —— 弹窗放不下长句，
详细说明放二级展开。这是硬约束，要写进规程。

### 9.6 validator 增补

- `emphasis_here` 出现时：四个子字段必须齐、`reason_kind` ∈ 四值、`evidence` 非空且引文可核
- `dimensions` 每项 `name` 非空且 ≤ 10 字
- **防“把维度当义项”**：`len(senses) > 1` 时，每个义项必须给 `distinction_note`
  （说明它与相邻义项为何是不同含义而非不同维度）—— 模型被迫给出理由，复核者也有得核

## 10. 主线：意义地图（v1.3：结构层面最重要的修正）

### 10.1 主线问题一句话

> **为一本书里的每个术语维护一张稳定的「意义地图」（义项 × 范围 × 维度），
> 划词只是在图上取值。**

之前的设计（每个划词请求跑一遍完整判断）把两件性质完全不同的事塞在了一起：

| | 建图（全局） | 定位（局部） |
|---|---|---|
| 问题 | 该词有哪几个义项？各自管到哪？有哪些维度？ | 当前位置读的是哪个义项？侧重哪一面？ |
| 需要视野 | **全书**（分布、定义段落、跨位置对比） | **就近**（本句 + 邻近段落 + L3） |
| 状态 | 可缓存、可累积、跨读者共享 | 只读地图，无状态 |
| 成本 | 高（一次完整分析） | 低（应是秒级、零模型请求） |

**不分开的后果**：① 每次划同一个词都在重建一次地图，贵；② 每次重建结果可能不同，
同一个词两次划词得到不同的义项划分 —— 对读者是灾难；③ 解释了之前所有“别扭”的地方：
为什么需要分布、定义段落、代回测试 —— 它们全是**建图**要用的，不是定位要用的。

**成本模型的改变**：L3 要对全部段落预生成（1424 条）；L4 只需对**被划过的词**建图。
词是稀疏的（一本书被划的可能就几十个）——这是 L4 比 L3 便宜的根本原因，
也意味着 **L4 不应照搬 L3 的批量预生成架构**。

### 10.2 主线直接推出两组工具与两套规程

**建图组**（对某个 term 跑一次，可缓存、可离线批量）

| 工具 | 作用 |
|---|---|
| `find_term_occurrences` | 分布 + 抽样：定范围、看分簇 |
| `find_definition_passages` | 找作者解释该词的段落（窗口 + 转折加权） |
| **`read_paragraphs_at`（新增）** | **批量读多处完整段落** —— 代回测试需要 A/B 两处的完整上下文，
现有 `find_term_occurrences` 只给 400 字摘要 |
| `read_concept_entry` | 读已建的地图（避免重跑、保持义项编号稳定） |

**定位组**（每次划词，必须快）

| 工具 | 作用 |
|---|---|
| `locate_term_context(window=1)` | 本句 + 邻近段落 + 段落的 L3 三段解释 |
| `read_concept_entry` | 取地图；命中则**不需要任何模型请求** |
| （降级路径） | 地图未覆盖该位置时，才调用建图组的工具做**局部增量** |

**不进工具，进材料注入**：译名卡。若 term 命中译名卡，直接把卡条目写进 materials ——
每次都需要的知识，不值得占一次工具调用。

**两套规程**（工具实现共用，判断目标不同）：

- `concept-mapping`：分布 → 定义段落 → 跨位置对比 → 三档代回测试 → 维度划分 → 范围与演化链
- `concept-locating`：**以地图为准**，只判“此处读法 + 是否达到侧重门槛”，不得改动地图

### 10.3 自审发现的新问题

16. **真 bug：`book` 的“跨两章证据”规则会误杀。** 若该词只出现在一章（全书即该章），
    模型给不出跨章证据，校验必然失败。修正：
    `len(证据章数) < 2` 时，只要该词在该书**出现章数 ≤ 1**，允许判 `book`。
17. **真 bug：抽样位置不能当证据入 occurrence 表。** `find_term_occurrences` 返回的
    samples 是给模型看的样本，不是“义项在此成立”的证据。地图的位置只能来自 evidence。
18. **定位可能落在义项交界**。该处既像 A 又像 B —— 不能硬选一个。
    输出应允许 `stance: "boundary"`（处于义项过渡中）。这不仅是容错，**这正是最有教学价值的位置**，
    与申报书里“过渡”的设计直接对应。
19. **词形归并**。「自在」与「自在存在」、「意谓」与「意谓着」是不同词形，
    不做自动后缀归并（会误并），而是在地图里维护 `aliases[]`，划词时先查别名。
20. **地图版本化**。新证据会改变义项范围 → 地图加 `revision`，划词结果标明基于哪一版；
    范围变化默认**不**改变已有 occurrence 的归属，只靠显式重建。
21. **结果缓存要按位置**，不能只缓存地图：同一位置重复划词应得到**相同的侧重理由**，
    否则每一次划词侧重都在变。
22. **地图不存在时的降级**：先给最小可用的局部快答（快），后台建图；
    下次划该词就用完整地图。不要为了等一张地图让读者干等。
23. **维度数 vs 弹窗长度**：多维度必然多维度解释，但弹窗放不下。
    所以长度上限只约束**单条**（reading ≤ 300 字、维度名 ≤ 10 字），
    条目数量不限，由前端折叠（默认只显示与当前位置相关的维度 + “还有 N 项”）。
24. **地图质量是一切的乘数**：建图若把维度当义项，后续所有划词都会错。
    所以地图必须有人工可修正入口（v1 至少要有“待核稿”标记与可编辑义项归属）。

## 11. 录入期预建“全书视野”（v1.4）

读者要求：**刚录入书目时就先建好核心概念的全书视野**，这样划到高频核心词时
不需要现场做全书分析。方向正确，但需要先解决“哪些词、多少个、怎么定下来”。

### 11.1 三层（成本与响应分开）

| 层 | 时机 | 用法 | 产物 | 成本 |
|---|---|---|---|---|
| **L0 分布** | 录入时 | **纯统计，零模型** | `term_candidate` 表 + 每个候选的分布缓存 + 段落锚点索引 | 秒级 |
| **L1 地图** | 录入后后台 | agent 建图（仅核心词） | `concept_sense` / 维度 / 范围 / 演化链 | 一次性，约 K×5 次请求 |
| **L2 降级** | 划词时 | 局部快答 + 入队补建 | 临时结果 + 后台建图任务 | 少步数 |

**关键**：即使 L1 还没跑完，划词时也能秒级拿到 **L0 分布**（判是否分簇所需的最重要部分）。
所以“全书视野”不是一步到位，而是从 L0 开始可用。

### 11.2 L0：核心概念怎么提名（纯统计，可解释）

三个信号，**任一命中即提名**（不靠模型，可靠性来自规则）：

1. **在译名卡/术语表里** —— 人工给定的白名单，现成（`docs/reading_semantics.md` 书目知识段）；
2. **出现在章节标题里** —— 作者自己划的重点（“感性确定性”“知觉”“力与知性”）；
3. **章覆盖度 ≥ 50% 或总频次 ≥ 阈值** —— 全书分布广的词。

HTML 里保留的强调标记（`<strong>` / `<em>`）是**第四个可选信号**：作者首次定义术语时常加格式 —— 需先验证各书源是否普遍保留。

### 11.3 数量：不预设，用分布断点定

把提名词按“（章覆盖度, 频次）”排序，看长尾开始的位置，取断点前的作为“核心”。
好处：可解释、可调、不拍脑袋；书与书之间自动适配（有的书 20 个，有的书 60 个）。

### 11.4 “一开始怎么确定”：统计提名 + 人工确认

**核心概念的判定不交给模型**，理由：① 成本可控；② 可解释；③ 地图质量是乘数，
不能让模型一次误判污染全局。所以：

```
录入 → L0 统计提名（term_candidate 表）→ 人工过一眼（可增删改）→ 建图队列 → L1 地图
```

第二步复用了已有的“待核稿”思路，界面成本低；也是全书视野的质量闸门。

### 11.5 热度自然浮现（解决“一开始猜不准”）

建图队列额外维护一个“**被划次数**”计数器：被划得多的词**自动插队建图**。
这样不必一开始就把核心词猜全 —— 白名单 + 标题词先建，剩余的让读者行为自己浮现出来。

### 11.6 划算的顺带产物

L0 的那次全书扫描自然就能产出两个小索引（成本几乎为零）：

- `term → 位置分布`：让 `find_term_occurrences` 秒级返回（不必每次重扫 1.1s）；
- `段落 → 命中的锚点词`：让 `find_definition_passages` 秒级初筛。

即：录入时多花一次全书扫描，后续所有建图与定位都快。

# 14. 结构层：章-节-子节层级（语义层的上下文来源）

语义层要实现的核心是：**生成合乎逻辑安排的文本，且上承章节结构、下接术语解释。**
逐段孤立解释做不到这一点 —— 实测 17% 的段是硬切分切断的半截话，孤立解释只能写套话。

## 14.1 现实约束

层级来源按优先级三级（详见 §15）：① `heading_json`（epub 源在入库时抽的 h1-h6）
② 文本行模式推断（txt 源）③ 模型扫一章（未实现）。**这本《精神现象学》是 txt 源**——
`heading_json` 为空、`content_html` 只有 `<br>`，所以走 ②；它的标注格式（方括号批注 +

## 14.3 设计要点：**层级本身就是自适应的上下文窗口**

- 窗口选择：取包含本段的**最深一层子节**，要求装下 ≥3 段；不够就往上走一层；
  节点超过 6000 字则退回「本段 ± 2 段」的局部窗口。中位 2035 字 ≈ 2.7k tokens，可承受。

## 15.4 归属判定（只解释原著部分）：判据修正

用户指出两点，已采纳：
1. **核心是「非作者」** → 判据相对于**本书作者**（`books.authors`），不是相对于原典作者。
   对一本「解读类」书，整本都是那位解读者的正文，**没有附文要排除**。
2. **删掉「文本自称」判据**（解读类作者也会自称「笔者」，会误判）。

原则：**默认在解释范围内，只排除有强证据的附文章节**（非对称成本：错排丢掉整章正文，
漏排只是多花钱）。判据：章标题（总序/译序/译后记/编者前言/出版说明/目录/附录，
且**不是作者本人的序言**）+ 章开头署名为他人 + 章内版权页特征密度。
广告文本是**另一类**问题（段级数据质量规则，实测 16 段），不是归属问题。

实测这本：章 0（123 段、7%、标题是文件名）= 版权页 + 译者导言 + 目录 → 排除；
章 1「序言：论科学认识」是黑格尔自己的序言（"真理是全体"在那儿）→ **必须留**。
