# 二、项目申请理由

## （一）项目背景和意义

### 一、项目背景

哲学社会科学经典文本通常篇幅长、概念密度高、论证层次复杂，且高度依赖思想史、文本语境和作者的问题意识。对读者而言，真正的困难往往不只是“知道某一段说了什么”，而是需要同时处理四个相互关联的问题：

1. 这本书围绕什么问题展开，总体结构和论证路线是什么；
2. 各章在全书中承担什么功能，章节内部如何推进论证；
3. 具体段落中的句子、术语、转折和指代关系如何理解；
4. 核心概念在文本中如何定义、辨析、演变并与其他概念发生联系。

传统阅读依赖读者自行建立上述结构，过程耗时且容易遗漏；现有AI阅读工具则大多以文献检索、摘要生成或一问一答为中心，能够快速给出局部答案，但缺少面向长文本深度阅读的分层工作空间，也难以把生成内容稳定地锚定回原文。通用聊天模型还可能出现脱离上下文、混淆概念、忽略论证前提等问题，读者难以核验其依据。

因此，本项目提出“智驱思阅”：一个以Agent为执行核心、以原文证据为约束、以读者编辑和复核为最终裁决的哲学社会科学辅助阅读工具。项目不以替代读者判断为目标，而是把长篇文本整理成可阅读、可追溯、可修改的辅助材料，让读者在全书、章节、段落和概念四个尺度之间来回切换，形成自己的理解。

### 二、项目的目标与意义

本项目的主要目标是：面向哲学社会科学经典文本，开发一套可在本地运行的辅助阅读工作台，完成从书籍导入、文本定位、分层生成、来源核验、人工复核到笔记与对话使用的完整闭环。

具体目标包括：

1. **建立四层阅读工作空间。** 提供全书层、章节层、语义层、概念层四种阅读尺度，分别回答“全书如何展开”“章节如何论证”“段落如何理解”“概念如何辨析”四类问题；
2. **实现Agent驱动的辅助内容生产。** 由多个承担不同阅读任务的Agent生成结构化辅助材料，支持任务排队、进度事件、取消、重试和结果复核；
3. **保证生成内容可追溯。** 每一条解释、论证步骤或概念说明尽可能绑定章节、段落、文本指纹和原文引文，读者可以从辅助内容回到原文核验；
4. **保留读者的最终控制权。** AI生成的内容先进入候选稿或待核稿区，读者可以编辑、修订、采纳或放弃，不把模型输出直接当作定论；
5. **形成可复用的工程底座。** 将书籍、笔记、对话、任务等业务数据保留在Server端，把模型执行放入独立Agent服务，通过版本化接口和受控工具连接，便于后续扩展与维护；
6. **开展小规模应用评估。** 通过专家评审和读者使用实验，检验工具对文本理解、论证把握和概念辨析的实际帮助。

项目的实践意义在于：为哲学社会科学经典阅读提供一个结构清晰、来源可查、可编辑的AI辅助环境，降低长文本阅读中的信息整理成本；同时为数字人文工具的设计提供一个“Agent执行、证据约束、读者复核”的可运行样例。

项目的探索意义在于：把阅读任务转化为可分工、可校验、可追踪的Agent任务，探索生成式AI在人文社科阅读场景中如何从“给答案”转向“提供有依据的阅读支持”。

## （二）国内外研究现状综述

### 1. 研究现状调研

**（1）AI学术检索与文献发现工具**

近年来，Elicit、Consensus、Scite等工具已经能够进行语义检索、论文发现、摘要生成和证据汇总。这类工具提高了文献检索效率，但其核心目标仍是“找到资料”和“概括资料”，对单部经典著作的论证结构、章节推进、段落语义和概念网络缺少专门支持。

**（2）长文本问答与摘要工具**

NotebookLM等工具通过多文档整合、结构化摘要和问答交互提升了长文本处理效率；ChatGPT、Kimi、DeepSeek等通用对话模型也具备较强的长文本理解与生成能力。然而，这类工具通常以用户提问为起点，以片段化回答或摘要为终点，难以主动组织一部书的整体结构，也难以把所有结论稳定地绑回原文位置。对哲学社会科学阅读而言，回答“这段话是什么意思”并不等于完成“这本书如何论证”的理解。

**（3）多Agent与工作流框架**

AutoGen、MetaGPT等框架支持多Agent角色分工、任务编排和工具调用，为复杂任务自动化提供了工程基础。但现有多Agent系统多按检索、生成、评估等功能划分角色，较少围绕“阅读工作本身的结构”组织任务，也普遍缺少对书籍数据、笔记数据和引用证据的统一约束。

**（4）数字人文与阅读工具**

现有电子阅读器主要提供目录、搜索、书签、标注和笔记功能，AI能力多为外挂式问答；数字人文平台则偏向语料整理、文本挖掘和可视化研究，普通读者难以直接用于逐章逐段的日常阅读。阅读界面、Agent任务、笔记系统和引用证据往往彼此分离。

### 2. 现有研究的不足

（1）**阅读目标停留在信息获取层面。** 现有工具擅长检索、摘要和问答，但未能围绕“重建文本结构、理解论证过程、辨析核心概念”组织阅读支持。

（2）**辅助内容与原文之间缺少稳定锚点。** 生成内容往往以自由文本返回，读者难以判断依据来自哪一章、哪一段、哪一句。

（3）**缺少面向长文本的分层工作空间。** 现有工具多为单轮问答或整篇摘要，无法让读者在全书、章节、段落、概念之间连续切换。

（4）**Agent能力缺少数据权限边界。** 通用Agent可以直接访问文件或数据库，容易混淆业务数据与模型执行；对于需要长期保存的书籍、笔记和对话，需要明确的数据所有权和访问边界。

（5）**生成结果缺少人工复核流程。** 模型输出往往直接展示，缺少候选稿、待核稿、编辑、采纳和冲突处理机制，难以适配学术阅读对可靠性的要求。

### 3. 调研结论

因此，本项目的切入点是：**不以某一种阅读理论预设读者，而是从文本本身的层次结构和真实阅读任务出发，把全书、章节、段落、概念四个尺度组织为可操作的工作空间；以Agent承担分层生成任务，以原文证据约束生成内容，以读者复核保证最终质量。** 这既区别于通用问答工具，也区别于仅提供标注功能的传统阅读器。

# 三、项目研究内容

## （一）项目研究的主要内容及目标

### 1. 四层阅读工作空间的设计

本项目把“阅读一部哲学社会科学著作”拆成四个互补的工作尺度。四层不是互斥的知识等级，也不是固定不变的线性流程，而是同一文本在不同尺度上的阅读任务：

| 层级 | 阅读问题 | 主要输出 |
| --- | --- | --- |
| 全书层（L1） | 这本书围绕什么问题展开？总体结构、核心论点和章节关系是什么？ | 全书问题意识、结构地图、论证主线、章节关系、核心概念清单 |
| 章节层（L2） | 本章在全书中承担什么功能？论证如何推进？在哪里转折？ | 章节定位、论证步骤、关键转折、承接关系、证据位置 |
| 语义层（L3） | 这一段说了什么？句与句、段与段之间是什么关系？ | 要点提炼、通俗解释、句段关系、上下文说明、原文引用 |
| 概念层（L4） | 这个概念在文本中如何定义？有哪些常见理解？与哪些概念相关？ | 术语定义、多义辨析、概念关系、文本证据、使用范围说明 |

**四层设计的文本学依据：**

1. **全书层与“整体—部分”循环。** 诠释学传统强调，理解一部作品既要从整体把握部分，也要通过部分修正整体。全书层先给出问题意识、结构地图和章节关系，为后续阅读提供可修正的整体框架；章节层和语义层再反向补充、校正这个框架。
2. **章节层与论证分析。** 哲学社会科学著作的章节通常不是简单的内容容器，而是论证单元。借助论证结构分析，可以识别章节的主张、理由、证据、限定和转折，避免把章节阅读降格为内容摘要。
3. **语义层与文本细读。** 文本细读关注词语、句式、指代、转折和上下文关系。语义层不替代原文，而是把段落中的关键句、难句和逻辑关系标出来，帮助读者回到文本本身。
4. **概念层与概念史/概念分析。** 哲学社会科学文本中的核心概念往往具有多义性、历史性和论战性。概念层需要区分日常用法、作者用法和不同语境中的含义，并通过概念关系网络展示其位置，而不是给出一个脱离语境的“标准答案”。

四层之间不是单向流水线，而是“整体提供约束、局部反馈修正”的关系：全书层为章节层提供位置和问题框架，章节层为语义层提供论证语境，语义层为概念层提供原文证据；概念层和语义层发现的不一致，又可以反馈到章节层和全书层，形成可修订的阅读闭环。

### 2. Agent驱动的任务组织

项目将每一层阅读任务转化为可由Agent执行的明确任务，并保留人工复核环节：

- **全书概览任务：** 在通读全书目录、章节标题和关键段落的基础上，生成全书问题、结构、论证主线和章节关系；
- **章节论证任务：** 读取指定章节的标题树、段落和上下文，输出章节定位、论证步骤、转折和证据；
- **语义解析任务：** 针对指定段落生成要点、释义、句段关系和上下文说明；
- **概念辨析任务：** 从选中的术语或段落出发，结合原文证据生成定义、辨析和概念关系；
- **对话任务：** 在书籍范围内回答读者问题，支持引用选段、章节和多轮对话；
- **复核任务：** 对生成内容进行独立检查，标记证据不足、范围越界或结构不一致之处。

每个任务具有明确的输入范围、输出结构、请求预算、工具预算和超时限制，支持取消、失败重试和中断恢复。任务结果先进入候选稿或待核稿，不直接覆盖原文或读者笔记。

### 3. Server与Agent分离的工程结构

项目采用“Server管数据、Agent管执行”的结构：

- **Server：** 管理书库、章节、段落、笔记、对话、任务状态和页面接口；拥有业务数据库的读写权；向前端提供版本化API；
- **Agent服务：** 只接收任务、模型配置和工具描述，不直接打开书籍数据库；需要读取原文、保存结果或校验提交时，通过带认证的内部回调请求Server执行；
- **接口契约：** 使用版本化请求模型和结构化输出，Agent与Server可以独立替换、测试和部署；
- **事件流：** 任务进度和对话增量通过SSE返回，支持断线续读和状态恢复；
- **本地优先：** 书籍、笔记和对话保存在本机，默认不依赖外部业务数据库，便于个人使用和教学演示。

这一结构的目标不是增加系统复杂度，而是明确数据权限、故障边界和可替换性：模型执行出现异常时，阅读和已有数据仍然可用；未来更换模型或Agent实现时，不需要重写阅读器和业务接口。

### 4. 可追溯的生成与人工复核

为保证辅助内容不是“无依据的答案”，项目在生成和展示两个环节加入约束：

1. **结构化输出：** 任务要求模型按照预定义字段返回内容，并对章节、段落、指纹和引文进行标注；
2. **原文锚定：** Server对引文和位置进行校验，前端可从辅助内容跳转到对应原文；
3. **候选稿机制：** Agent生成结果先保存为候选稿，读者可以在任务面板查看、编辑、采纳或放弃；
4. **复核与修订：** 生成结果可以经过独立复核；复核不通过时保留问题说明，必要时重新生成；
5. **冲突保护：** 当原文或已有笔记在任务运行期间被修改时，保存操作应提示冲突，避免覆盖读者内容。

### 5. 原型系统与验证

原型以Web阅读器为载体，用户可以：

- 从书库导入EPUB/TXT并继续阅读；
- 在目录、搜索、书签之间切换；
- 触发全书、章节、段落或概念层任务，查看实时进度；
- 查看段落旁注、概念解释和原文引用；
- 在对话中引用原文、章节或多段材料，进行追问；
- 编辑四层笔记，保存并导出；
- 在任务面板中取消、重试、审阅和采纳候选稿；
- 在设置页配置模型服务、密钥、超时和预算。

**研究重点：**

- 四层任务之间的输入输出边界和上下文组织；
- 生成长文本时的结构一致性、引用准确性和概念一致性；
- Server与Agent之间的契约、权限、取消和恢复；
- 读者如何理解、修改和信任AI生成的辅助内容。

**研究难点：**

- 哲学社会科学文本的概念多义、隐喻表达和论证省略；
- 长文本跨章节上下文的取舍与压缩；
- 生成内容的稳定性、可核验性与幻觉抑制；
- 辅助内容对阅读过程的实际帮助如何测量；
- 在不替代读者判断的前提下设计合适的人机分工。

**研究思路与方法：**

项目采用“需求研究—原型迭代—专家评审—用户实验—修正”的循环：

1. 通过文献调研、教师访谈和读者访谈确定四层任务的具体问题；
2. 以真实经典文本为语料，按层实现任务和界面，完成小范围可用性测试；
3. 邀请人文社科教师或研究生对生成内容进行准确性、有用性和证据充分性评审；
4. 开展小规模读者实验，比较使用本工具与通用问答/摘要工具时的阅读表现和主观体验；
5. 根据反馈修正任务说明、输出结构、界面和评估指标，形成可复现的实验记录。

## （二）项目创新点

### 1. 以阅读尺度组织Agent任务，而不是按通用功能堆叠

现有工具多以“检索、摘要、问答”等功能组织AI能力，本项目以全书、章节、段落、概念四个阅读尺度组织任务。每个尺度对应不同的阅读问题、材料范围和输出结构，使Agent的服务对象从“泛化的问答”变成“具体的阅读工作”。

### 2. 以原文证据约束生成，以读者复核完成闭环

项目不是让模型直接给出结论，而是要求生成内容尽量绑定章节、段落、指纹和引文，并通过候选稿、复核、采纳和冲突保护，把读者放在最终决策位置。这使AI输出从“可信口吻的答案”变成“可检查的阅读材料”。

### 3. Server与Agent分离，明确数据所有权

项目将业务数据保留在Server，将模型执行放入独立Agent服务，通过版本化契约、工具回调、认证和预算控制连接两者。Agent不直接接触书籍数据库，既降低了数据被越权读写的风险，也使模型服务可以独立替换和测试。

### 4. 阅读、笔记、对话和任务共享同一套文本坐标

目录、搜索、段落旁注、对话引用、笔记和Agent任务共用章/段坐标和文本指纹，读者可以从任意一条辅助内容回到原文，也可以把原文选段带入对话或笔记。这种一体化工作流比“阅读器+外挂聊天窗口”的组合更接近真实阅读过程。

# 五、项目实施条件

## （一）数字资源条件

项目可使用华东理工大学图书馆的中外文学术期刊和哲学社会科学数据库；使用国家哲学社会科学文献中心等公开资源获取经典著作和研究成果；使用Project Gutenberg等公共版权文本作为补充语料。验证语料以哲学、社会学、政治学等领域的经典著作为主，兼顾中文文本与译本。

## （二）算力与模型服务

项目使用兼容OpenAI Chat Completions的模型服务进行推理，可根据任务需要选择通义千问、DeepSeek等模型，并通过本地配置管理服务地址、模型名、密钥和请求预算。开发环境支持本地Server与独立Agent服务并行运行；如后续需要更大规模实验，可使用学校或云平台的GPU/CPU资源。

## （三）软件与技术条件

原型采用Python、FastAPI、SQLite、OpenAI Agents SDK和静态Web前端；书籍数据按书保存在本地数据库中，Agent执行状态单独存放；接口使用版本化HTTP API和SSE事件。项目使用Git进行版本管理，已建立离线测试、接口测试和浏览器验收脚本。团队具备继续开发、调试和部署的条件。
